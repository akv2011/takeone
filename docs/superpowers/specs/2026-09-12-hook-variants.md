# Opening hook variants

Approved feature scope: create three different openings from one completed owned video. This first control changes a large timed opening title (up to three seconds), preserving footage, narration, music and duration. It does not claim to regenerate speech. The creator supplies three distinct editable titles; title playback previews are free and batch export reserves three normal generations atomically. Every export is an owned child version. Exact batch retries reuse the same three jobs; changed content rejects before billing. Insufficient allowance or queue space rolls back the whole batch. Each output follows the existing free watermark rule.

Use a bounded `hookTitle` immutable job input and a separate `hookVariants:request` mutation. Worker renders the title directly, never through the LLM router. Paired caption archives are rebuilt with the title on the clean source so later caption edits keep it. Existing flattened source overlays remain. UI has explicit price, three labelled inputs, preview and result links, fenced by account/job lifetime. Verify owner isolation, atomic debit/refund, duplicate retries, worker branch and real title frames/audio/full decode.

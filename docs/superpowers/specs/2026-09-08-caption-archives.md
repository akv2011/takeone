# Retained caption layer artifacts

New managed stock/topic, clip and upload renders with timed captions retain an additional video without that TakeOne caption layer plus JSON timing metadata. The executor exposes the pre-caption input before temporary files are deleted. The archive applies reproducible subsequent effects to that input, validates/decodes the result, copies it outside executor scratch space and stores version-1 style/cues metadata bounded to 512 KiB.

The worker uploads the pair privately as `videos/<job>/<lease>-clean.mp4` and `captions/<job>/<lease>.json`. Completion accepts both or neither and checks their exact job/lease paths. Upload failure prevents accepted completion; normal worker retry/refund behavior applies. Temporary archives are removed with the worker directory. Unaccepted uploaded objects still need the general orphan-retention policy.

Embedded text in source footage is not removed. Existing-export edits do not create an archive because the input may already contain TakeOne captions. Provider-selected post-caption overlays are excluded: their exact source assets must be persisted before they can be replayed faithfully. Supported post-caption operations are watermark, music using a local track, trim/clip, speed, format, title and zoom. Older/unsupported jobs continue without archive keys.

Studio now offers clean, bold, short-phrase and no-caption edits for completed versions with an archive. An owner-scoped mutation checks the paired source paths, snapshots ancestry and retained music attribution, and uses the normal idempotent queue and allowance transaction. The worker downloads the bounded private pair, validates version/timing/text/size against the video duration, and renders from the caption-free source without transcription or model calls. Each result retains that same clean base and timing for subsequent restyles. Source-embedded text remains; selecting none removes only the saved TakeOne layer. Normal free-plan branding still applies. Existing branding and music may already be baked into this clean-of-captions file. It is not a fully reversible editing project.

Additional video storage and repeated post-caption effects increase cost/render time. Measure those with real cloud jobs before acceptance. The existing constant-frame-rate speed operation can retain two boundary frames at 30 fps; timestamp metadata is mapped exactly, but frame-addressable trimming remains separate work.
